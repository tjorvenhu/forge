# ADR 0007: Phases 2 and 3: configuration, composer, remote, terminal, automations

Date: 2026-10-10 · Status: accepted

## Editing the Claude configuration

FORGE now writes to Claude's own files on explicit request: `~/.claude/CLAUDE.md`,
`<projekt>/CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, skills (`skills/<name>/SKILL.md`),
subagents (`agents/<name>.md`) and the `hooks` key in `settings.json`. Rules:
paths are only built in the sidecar from (scope, project, name); a `.bak` before every overwrite;
conflict detection via mtime; hooks are checked structurally, all other settings stay unchanged.
`CLAUDE.local.md` goes into `.git/info/exclude`. MCP servers are managed exclusively via `claude mcp add/remove/list`.

## Composer

- **Attachments**: images (png, jpg, gif, webp) as image blocks, PDF as document block, text files
  as text block; max. 10 files, 10 MB per file, 20 MB in total. Sources: file dialog, paste,
  drag and drop (Tauri delivers real paths). Sensitive paths (e.g. `~/.ssh`) are rejected.
- **Slash commands** from `supportedCommands()` (live) or a short probe in the project folder.
- **Checkpoints**: `enableFileCheckpointing` with its own `uuid` per user message; "Rewind files"
  calls `rewindFiles` with a preview (dryRun).

## Remote Control

Replaced by ADR 0008. Original state: the SDK has no documented switch to make a running headless Session remotely controllable. FORGE
therefore starts the official command `claude remote-control --name "FORGE · <Projekt>"
--permission-mode <Profil>` per project and reads status and link from the output. Sessions started from the phone
belong to the CLI; the FORGE blocklist (PreToolUse hook) does not apply there, but the profile's permission mode
does. At that time Autonomous was only passed on if the FORGE gate was open (gate since removed, see ADR 0004). Folders that Claude
does not trust yet are approved in the embedded terminal with `claude`.

## Terminal

PTY in the Rust shell (`portable-pty`), output as events, input via commands. Only the
user's shell and the Claude CLI can be started (path is checked for `claude(.exe)`). Bundled git/gh in PATH.

## Git: push, pull, PR

Push never with force, `main`/`master` only after confirmation by typing the branch name, pull only
`--ff-only` with understandable options on divergence. PRs via `gh pr create`, title and description
optionally from Claude based on commits and diff.

## Automations

- **Tags**: plan-first, auto-test, auto-commit, auto-push, review-required, no-network, sandbox-only
  (description in the project). Auto-commit only takes files that were not modified before the run,
  no sensitive files or build artifacts, and only with green tests.
- **Feature workflow** (removed again in ADR 0008) as a persistent state machine (table `workflows`). Waiting steps survive
  a restart; running steps are marked as interrupted after a restart.
- **Scheduled tasks** (removed again in ADR 0008, table `schedules`), checked every 30 s, executed at most once per slot,
  only while FORGE is running.
- **Parallel agents**: Git worktrees under `<eltern>/.forge-worktrees/<projekt>/`, registered as a separate project
  with `parentId`. Removing deletes only the folder, branch and commits remain. The worktree's Session,
  terminals and dev servers end first, otherwise Windows refuses to delete the folder.
  Since October 2026 the UI is an "Agents" tab in the workspace, no longer a separate menu item.
- **Test command**: the only place with a shell (`spawn(..., { shell: true })`), because the command comes from the
  user's project settings, never from the repository or from Claude.

## Miscellaneous

- `freezePrototype` is off: editor and terminal libraries set prototype methods when loading.
- Project templates removed; "Create new" only creates a folder (+ git), optionally a GitHub repository right away.
